# bench

pnext's benchmark suite. Most fixtures in `bench/fixtures/` are a plain Next.js
App Router app, so the identical source is measured twice: once under `pnext`
(run straight from this repo's `bin/pnext`) and once under `next` (from the
fixture's own `node_modules`). `visible` is the one exception — it has a source
tree per framework, see below. No numbers are compared across different apps.

## Run

```sh
bun install     # once, in the repo root
bun bench       # every fixture, both frameworks, 3 runs
```

Fixture dependencies (`next`, `react`, `react-dom`) install themselves on first
use. More control:

```sh
bun bench/run.ts ssr                      # one fixture: hello-world | ssr | dashboard | visible | all
bun bench/run.ts all --framework=pnext    # both | pnext | next
bun bench/run.ts ssr --runs=5             # runs per metric (default 3)
bun bench/run.ts visible --bundles        # payload only: one untimed build, no timed runs
```

Each run prints a `metric | pnext | Next.js | ratio` table per fixture, the
client runtime bundle sizes, and the targets table.
[`reference/performance.md`](../reference/performance.md) is updated by hand
from that output.

## Fixtures

| Fixture     | Shape                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ssr`       | Root layout + global CSS, a home page rendering 50 items from a local data module, a page with `metadata`, a dynamic `posts/[slug]` route, and one client island (counter).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `dashboard` | Mid-size admin app: 30 routes across overview, analytics, customers, products, orders, invoices, inventory, reports, admin, settings, notifications, profile and a `(support)` route group, under a root shell plus five section layouts with per-section `metadata`, two `loading.tsx` and two `error.tsx` boundaries, and two `generateStaticParams` detail routes. ~970 rows of local mock data paginated into server-rendered tables, 15 hand-rolled client islands (active nav, dropdown, theme toggle, line/bar/donut inline-SVG charts, sortable headers, filter bar, tabs, modal, toast, multi-step form, command palette, copy button, profile form) and two server actions. Global CSS plus five `*.module.css`. ~109 modules, no UI dependencies. |

| `visible` | A landing page: server-rendered header, hero, features, logos, testimonials and FAQ, plus one interactive island (a pricing calculator) far below the fold that mounts when it scrolls into view. Two source trees, one product spec — see [`fixtures/visible/README.md`](fixtures/visible/README.md). |

`hello-world`, `ssr` and `dashboard` enable `compat.next` so a single source
tree runs on both frameworks. `visible` cannot: the tier it exists to measure
is core pnext's `dynamic(load: 'visible')`, which compat mode never reaches, so
it ships `visible/pnext` (core pnext) and `visible/next` (Next + `next/dynamic`
behind an `IntersectionObserver` gate) as two idiomatic implementations of one
product spec. Its README carries the equivalence rule that keeps them
comparable; `bench/run.ts` picks the tree per framework via the fixture's
`dirs`, so every other metric applies to it unchanged.

## Metrics

| Metric                 | What it measures                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Dev cold start         | Output dir wiped, dev server spawned on a free port, timed to its readiness banner.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Dev first page HTML    | The first `GET /` after ready — includes on-demand compilation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Dev warm request       | Median of 7 further `GET /`s on the same, already compiled route.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Dev server RSS         | Whole-process-tree RSS (parent + any spawned workers), read once right after ready + the 7 warm hits — never sampled at a random time.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| HMR save → visible     | A marker is appended to a rendered string in a page component; the page is polled until it serves the marker back. A 200 with stale HTML does not count.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Prod build cold (wall) | Process wall time of `pnext build` / `next build`, output dir wiped first.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Prod build warm (wall) | Process wall time of an immediate rebuild with the output dir retained and no source change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Prod build peak RSS    | `/usr/bin/time -l` (macOS) / `-v` (Linux) peak RSS over the build process, parsed from stderr.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Prod start (ready)     | `pnext start` / `next start` spawned on a free port, timed to its readiness banner.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Prod warm request      | Median of 7 further `GET /`s against the running production server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Prod server RSS        | Whole-process-tree RSS, read once right after prod ready + the 7 warm hits.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Framework install size | `du` of each framework's own package, not the fixture's total `node_modules` (shared by both): `next` + its platform `@next/swc-*` binary, or `@wular/pnext`'s npm-publish footprint (its `package.json` "files" list, since the repo resolves it to source rather than an installed build) + `preact`.                                                                                                                                                                                                                                                                                                                                                                                    |
| First-page client JS   | `<script src>` + `rel="modulepreload"` assets the built home page executes, fetched from each framework's own production server, raw and gzip (level 9). `noModule` polyfills and speculative `rel="preload"` hints for other routes are excluded on both sides.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Deferred client JS     | JS the first page fetches only after first paint, never as part of the initial execution: the chunk graph reachable from the initial chunks by following the asset paths they name as string literals — visibility islands, lazy router/runtime chunks. Same crawl, same gzip, on both frameworks, off each one's own production server; anything already counted as first-page JS is excluded. It sees chunks a chunk names; it does not see chunks whose URLs only appear in a server payload at navigation time, so Next's per-route navigation chunks are not in this number. Read it next to first-page JS, not instead of it: what one framework defers the other may ship up front. |
| Zero-island route JS   | Same measurement on a route with no client component anywhere in its tree (`ssr` only).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Client runtime bundles | pnext's router and router+hydrator runtimes, bundled and minified with esbuild: raw, gzip, brotli.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## Protocol

- Runs are sequential; nothing runs in parallel with a measurement.
- With `--runs` at 3 or more the first run is discarded, then medians are
  reported. Bundle sizes are deterministic and measured once, off the last build.
- Every dev/prod server gets a fresh free port, is killed with `SIGKILL`, and
  the port is swept afterwards, so a server never outlives its measurement.
- Ratios are `Next.js / pnext`: above `1.00x` means pnext is ahead.
- Bundle sizes come off a production build and are deterministic; `--bundles`
  measures only those (one untimed build per framework), which is the cheap way
  to check a payload change without paying for the timed suite.
- Machine noise is real — run on an idle machine, and prefer `--runs=5` or more
  when comparing across commits.
